# 静态图骨骼解析原型

版本 0.4.1，2026-10-12。目标：从单个人形静态图提取二维姿态，预览和检查关节，作为后续动作提取与动作库的起点。

## 界面与流程

仅视频与动画帧工作台在左侧聊天区上方提供独立的静态图上传区和骨骼 Hierarchy。用户可点击上传或拖入一张 PNG、JPEG、WebP；最大 30 MB。图片保存在所属工作台素材目录，成为当前图片预览，并自动调用 OpenAI 解析。

骨骼预览放在图片预览左侧。18 个固定人形关节按解剖关系建立树：骨盆、胸部、颈部、头部、左右肩肘腕及髋膝踝脚尖。左右是角色自身的左右。用户点击树或骨架上的关节，两处联动高亮；树支持折叠，预览可叠加原图。被遮挡或模型确定程度低于 0.5 的连线使用虚线；无法定位的点保留空坐标，不绘制。

解析中禁用替换与重复提交。错误保留图片并显示原因，可打开设置或手动重新解析。正常上传区继续处理聊天素材，静态图上传区不自动修改视频附件或 Prompt。已有聊天、视频和 Timeline 保留。

## API 与数据

使用当前工作台配置的 OpenAI 聊天模型及 App 级加密 Key，独立于聊天供应商选择，不调用 Claude。默认 GPT-6.1 Sol 使用 Responses API，图片为 normalized PNG data URL、detail high；历史聊天模型使用 Chat Completions。两者均请求 strict JSON Schema，不进行供应商切换或自动重试。

模型返回 subject_found、notes 与关节点数组。坐标以整张图片左上角 (0,0)、右下角 (1,1) 定义；缺失点的 x/y 均为 null。运行时校验人形主体、完整关节 ID 集合、重复 ID、坐标与主观确定程度范围、可识别关节数量；拒绝非人形或非法响应，不生成默认骨架。

姿态状态存在所属工作台 SQLite 的 poseWorkspace：sourceAssetId 与 analysis。analysis 记录源图、请求 ID、解析状态、模型快照、时间、关节和错误。业务 IPC 绑定工作台 ID，切换时继续写入原工作台；解析计入 localOperations，阻止进行中的工作台删除。重启时将中断的解析标记失败，不自动重发请求。

结构化输出依据：[OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 验证与边界

核心测试验证图像请求、强制 OpenAI 路由、strict schema、缺失关节处理、坐标和 ID 校验、缺少凭据、非人形失败、重复提交拒绝、持久化及中断恢复。桌面测试通过实际 file input 上传并请求隔离的本地 HTTP 服务，验证 SVG 骨架、Hierarchy、高亮、原图叠加及工作台之间的功能隔离。测试结果不代表真实 OpenAI 定位精度，未使用用户 Key 或消费额度。

当前是视觉语言模型的二维估计，确定程度是模型自评，不是统计标定置信度；不提供精确三维动捕、关节拖动修改、视频姿态提取、动作保存与组合、Wan 驱动或 FBX 导出。后续先验证真实人形图片的定位效果，再决定是否加入专用姿态检测器。

0.4.1 修正：图片与视频创作恢复原三列布局（左侧上下聊天、中间图片、右侧视频），不挂载骨骼组件；服务层拒绝该种类的骨骼 IPC 操作。已有素材与记录保留。
