# 骨骼编辑、动作提取与动作库

版本 0.5.0，2026-10-12。仅用于 `video-frames`（视频与动画帧）工作台；图片与视频创作保持原双聊天、图片、视频预览布局，所有动作 IPC 在服务层检查工作台种类。

## 使用流程

1. 上传静态人形图，OpenAI 解析完成后，在骨骼窗口开启原图叠加。拖动关节修正，方向键微调、Shift 加快；暂停编辑会自动写入工作台，可撤销/重做最近 30 次操作并恢复原始识别。Hierarchy 选择缺失关节后可补点。输入名称并保存，左侧已保存姿态可再次载入。
2. 在“视频动作与动作库”上传视频，或选择已在工作台的 MP4/MOV。设置起止秒数和采样 FPS，点击“提取连续骨骼”。使用随安装包提供的 MediaPipe Pose Landmarker Lite 本地检测器，CPU 推理在独立 Web Worker 中执行，视频不发给 OpenAI。默认 12 FPS，1–30 FPS、最多 1200 帧、最长 120 秒，视频仍遵守 50 MB 上传限制。
3. 提取完成自动选择动作。中间显示骨骼，右侧显示原视频对照及骨骼 Timeline。播放/暂停、滑条或逐帧选择保持骨架和原视频采样时刻一致；暂停后拖动关节修正当前帧，支持当前帧撤销/重做。无法检测的关节为 null，不绘制默认人体。
4. 输入名称、逗号分隔标签，保存到动作库。提供名称/标签搜索。“补点并平滑”仅插值由两侧有效关节包围的短缺失段，不外推前后缺失，默认补 ≤0.5 秒；可选 1/3/5/7 帧移动平均，1 表示不平滑。原始骨骼保留，可恢复。
5. 上传并修正新角色的静态姿态，选择动作并点击适配。按目标二维骨段长度重新定位动作关节，保留运动方向及相对根位移，创建独立动作变体。不同镜头或遮挡下的三维深度无法从二维动作可靠恢复。
6. 添加多个动作到顺序组合列表，调整顺序、0.25–4 倍速、1–10 次重复、镜像与 0–1 秒线性过渡，生成新的动作草稿。组合是二维插值，不包含物理模拟、足底锁定或上/下半身叠加。
7. 导出完整动作 JSON 或骨骼 MP4。MP4 使用 FFmpeg 从关节数据确定性绘制并编码为 H.264/yuv420p、24 FPS；不是重新请求 AI。静态姿态和动作分别存放在工作台 SQLite。

## 换角色视频

本版提供现有 MiniMax H3 视频参考入口：渲染骨骼 MP4，将目标角色图片与参考视频放入下方视频聊天，设置为 reference 并填入可修改的动作说明。此操作准备请求，不会立即提交收费视频任务；用户检查后点击既有生成按钮。

H3 视频参考并非姿态硬约束，角色一致性和动作跟随程度仍需实际生成验证。H3 参考片段需 2–15 秒，超出范围提示调整或导出。Wan 没有已配置的服务，本版未将 H3 入口标记为 Wan 推理；后续可在已有动作 JSON/视频基础上对接专用动作驱动服务，并按其骨架定义转换输入。

## 实现与数据

- `src/shared/pose.ts`：18 个标准人形关节、姿态/动作格式、插值、镜像、补点、平滑、二维适配。
- `electron/motions.ts`：工作台隔离、姿态快照、提取任务状态、帧校验、动作库、组合与导出准备。
- `src/ui/pose-worker.ts`：MediaPipe VIDEO 模式，单人跟踪。33 个检测点映射到标准 18 点，低可见性或画面外点保留缺失。头/骨盆/胸/颈使用规定的中点关系。
- `src/ui/motion-detector.ts`：在原视频指定时间采样，按单调时间戳检测，批次写入固定工作台。视频通过绑定实例 IPC 获取为 Blob，主窗口切换不会改变后台任务的数据归属。取消后后续批次拒绝；关闭后将中断任务标记失败，不自动重跑。
- `electron/motion-render.ts`：骨架离线绘制及 FFmpeg 编码，预览按动作变化失效。
- `PoseCanvas` / `joint-editor` / `MotionWorkbench`：拖动、键盘、撤销/重做、动作库、修正、组合和播放。

`motionWorkspace` 包含姿态快照 poses、动作 clips、当前动作 selectedClipId 与 extraction。每个帧记录相对时间、关节、原始关节以及来源时间；动作记录画布、采样 FPS、来源视频与片段起点、标签、是否入库、引擎、目标角色、生成的骨骼参考素材。动作 JSON 导出包格式为 ai-assets-motion/version 1。

## 离线模型与构建

安装 `@mediapipe/tasks-vision` 固定 0.10.32，官方 MediaPipe Lite 模型随 App 提供，不在用户启动时从外网拉取。`scripts/prepare-pose.mjs` 复制 WASM 并将检测代码打包为经典 Worker；Vite 把 public/pose 放到 dist。CSP 仅增加 wasm-unsafe-eval 与 self worker，保持禁止外部脚本。

模型地址：`https://storage.googleapis.com/mediapipe-models/pose_landmarker/pose_landmarker_lite/float16/1/pose_landmarker_lite.task`。
SHA256：`59929e1d1ee95287735ddd833b19cf4ac46d29bc7afddbbf6753c459690d574a`。
WASM/模型说明与 Apache-2.0 许可证一起放入 public/pose。缺少模型时构建明确失败。
官方接口依据：[MediaPipe Web 指南](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)。

## 验证及限制

核心测试覆盖姿态编辑/恢复/快照、片段范围、时间连续性、重复与取消、检测失败、补点边界、平滑恢复、动作保存、调速重复镜像过渡、目标骨段长度、重启和原工作台拒绝动作入口。

桌面测试实际运行打包的本地 CPU 模型，从官方人体示例制作的 2 秒静态视频提取 24 帧，验证检测链路、关节拖动、撤销/重做、姿态与动作保存、同步 Timeline、适配、组合和 H.264 参考编码。该样本不是运动精度基准，复杂真实动作、遮挡、快速转身、卡通人体以及生成视频的实际跟随效果仍需逐项验证。测试不消费用户额度。

当前未提供动作 JSON 导入、动作库删除、三维骨架、FBX 导出、动物骨架、手指/表情驱动、骨段刚性约束或精确脚底接触。已编辑的动画帧可继续使用已有图片编辑器；连续骨骼提取目前以来源视频为输入。
