# 二维角色绘制台

入口：新建工作台 → **二维角色绘制台**。这是二维切片角色的绘制和修整工具，
用户与外部 computer-use agent 使用相同界面和保存模型。

当前流程：**拆分部件 → AI 部件补画 → 装配与绑定 → 动作检查 → AI 生成动作**。

## 当前能力

- 导入 PNG 开始分层，或打开角色 ZIP / 工程 JSON。
- 内置上一轮实际生图实验生成的机器人样例；载入不会请求生图 API。
- 图层复制、新增透明补画层、重命名、显隐、锁定、透明度、绑定骨骼与层叠顺序。
- 顶部工具栏提供大小滑块和 px 数值输入；画笔与橡皮分别记忆大小，重新打开后保留。
- 默认画笔，连续拖动和松开完成；支持防抖、软硬度、不透明度、圆形笔刷光标和数位笔压感数据。
- 套索遮罩、手绘色块、平滑描线均支持拖动完成；逐点钢笔保留为可选模式。
- 底色和墨线通道、当前通道橡皮；软边和透明度在编辑与导出中保持一致。
- 光标位置滚轮缩放、空格/中键平移、抓手、Alt 临时吸管、画笔大小快捷键。
- 多边形轮廓遮罩、遮罩及笔画节点拖动、已有笔画样式修改。
- 撤销/重做、缩放、参考淡显、单层查看和独立骨骼动作回放。
- 工作台内自动保存；保存修订冲突拒绝覆盖另一窗口的新数据。
- ZIP 同时保存可编辑工程、运行时 PNG、骨架与动作、逐文件 SHA-256。

手动绘画、裁切和部件选择不调用生图服务；AI 补画仅在点击生成时调用配置的图片接口。原始图层 PNG、遮罩与笔画分别保留。
导入普通 PNG 时先建立根节点和源图层；可复制源图层，逐层画遮罩拆件。
已登记的骨架和动作可从角色包载入。当前支持 AI 骨架生成和手动关节编辑；尚无网格蒙皮或动作生成 API 接口。

## 绘画 agent 的操作流程

1. 打开指定工作台，确认工程和图层名称。只处理用户指定的部件。
2. 开启“仅当前层”和“参考淡显”。放大前重新读取画布边界，按实际画布位置操作。
3. 选“套索遮罩”，沿保留区域连续拖动，松开自动闭合；精确逐点描绘可切换“钢笔 · 逐点”。
4. 选“节点调整”，在“编辑对象”中选择遮罩或笔画，拖动圆点微调。
5. 补隐藏结构时新增透明图层，选正确的绑定骨骼和层叠顺序，再用底色填形或画笔补画。
6. 墨线使用独立通道；橡皮只作用于当前通道，底色橡皮也能擦底图。
7. 查看右侧动画，分别检查接缝、遮挡和轮廓；不能只看骨骼接点是否重合。
8. 等待“已保存”，导出工程备份。保存冲突时先导出当前草稿，再重新载入已有数据。

快捷键：B 画笔、E 橡皮、L 套索、G 色块、P 平滑描线、A 节点、I 吸管、H 抓手；
[ / ] 调整笔刷大小；空格/中键拖动；滚轮缩放；0 适合窗口；
Cmd/Ctrl+Z 撤销；Shift+Cmd/Ctrl+Z 重做；Cmd/Ctrl+S 保存。
逐点模式下 Enter 或双击完成；Esc 取消。图层锁定后不接受画布笔画和节点修改。

项目没有捆绑自主 computer-use 模型或代理调度服务。上述工具可供外部 agent 操作。
当前验证使用 Electron 的真实 Chromium 鼠标/键盘输入，未直接修改工程来替代绘画操作。

## 快速选择（0.10.11）

快捷键 W。用可调大小（0.1–200px，滑块、数值与 []）的笔刷涂抹部件内部；选择笔刷大小独立记忆。加选/减选支持多笔累积，自动贴边可以关闭以便精确修边，边缘容差范围 5–100。点击“提取为新部件”会复制独立图层并隐藏源图层，原图位图保留；选区可撤销、持久化并导出透明部件。

本地 Web Worker 对最长边最多 1024px 的源图进行颜色主簇与连通区域扩展分析。每笔在笔刷附近补齐相似色，小面积越界会按主要颜色排除，透明像素阻断扩展，小封闭纹理孔洞填补，最多保留三分析像素的深色描边。分析范围约为笔刷半径的三倍，防止无限扩散；不同色块分笔加选。它不识别“手臂/头部”等语义，没有清晰颜色边界时需要减选或关闭自动贴边手工修正，不补绘被遮挡的角色内容。

像素遮罩以二进制 RLE 记录在 artwork.selectionMask，坐标覆盖角色画布，保留孔洞及不连通区域；旧的多边形遮罩工程仍兼容。编辑器、动作预览和导出共同使用 rasterCutout 应用遮罩。tests/cutout-selection.test.ts 验证边缘、漏涂、越界、孔洞、描边与加减选；scripts/cutout-selection-smoke.cjs 使用真实 Chromium 指针输入检查涂抹、撤销、提取、透明导出与重启恢复。

## 连续拆分工作流（0.10.12）

参考 Spine 将素材准备、装配、动画区分的流程，绘制台提供三个阶段：拆分部件、装配与绑定、动作检查。拆分阶段固定从 reference 原图采样，将临时遮罩及名称写入 selectionDraft；创建前不改变已有部件。命名后创建部件会保持原图、保留快速选择工具并清空临时草稿，可以直接继续拆下一块。重编辑已有部件时，确认前也只修改草稿，保存后原位更新部件。

原图单独出现在“参考原图”，不参与运行时部件及图片导出。左侧“已创建部件”提供透明缩略图、重命名、删除，删除支持撤销。原图对照、拼合预览、单独查看独立于选择取样；从结果视图重新涂抹会自动回到原图。装配阶段提供绘画修补、拖动/按钮调整绘制顺序、父骨骼和关节点设置及绑定。动作检查提供角度滑块与初始姿势恢复，测试姿势不修改原位注册。

旧工程中明确标识为 source、尺寸覆盖画布且没有绘画笔触的原图层会迁移为 reference；已提取的部件保持不变；原图层已有套索遮罩或补画时，另建参考原图并保留原有部件。只有旧原图上存在尚未提取的选区时迁移为 selectionDraft。没有完整原图的旧分层工程仍可装配和修补。

验证：tests/cutout-workflow.test.ts 覆盖连续创建、临时草稿隔离、更新、迁移、删除、排序与持久化；scripts/cutout-selection-smoke.cjs 通过真实 Chromium 指针输入跑通连续两块、修改选区、命名、删除撤销、关节设置、动作检查、未完成草稿恢复，以及参考底图和临时选区不进入运行时导出。

## 快速选择性能修复（0.10.13）

拖动预览使用独立的透明画布，最长边 1024px；底图及已完成选区不会随每次指针移动重画。原图分析像素首次使用时上传到 Worker，在参考图替换后失效；后续笔画只发送轨迹及选区参数。图片加载池按位图去重，复用原图与部件共用的 PNG。图片数据签名通过 useMemo 避免在每一帧重新拼接所有 base64。

本地算法把颜色距离改为等价的平方距离，描边与结果合并只扫描笔画附近的包围盒，RLE 编码使用索引循环。常规笔画基准中位数约 28ms → 12ms；密集大笔刷约 104ms → 102ms，两个基准的选区完全一致。保存校验按共用位图去重，后续保存复用 PNG 尺寸缓存，新的图片字节和部件注册仍重新校验；文档容量用 JSON 结构长度加位图长度精确计算，避免重复序列化 base64。1440px 原图、3 个部件、约 1788 万字符的工程，热保存约 375ms → 85ms；首次保存约 466ms → 202ms。完整工作区 JSON 存储仍有开销，不能将这些耗时视为所有设备和图片的保证。

可复核结果：output/cutout-performance-review/report.json。桌面测试使用 2048px 原图断言拖动时底图重画不超过一次、连续笔画复用一次像素上传，并检查同尺寸新原图会正确使缓存失效。

## 图片自由移动（0.10.14）

装配与绑定阶段默认使用“移动图片”（V），点击部件的可见像素直接拖动；透明区域穿透到下层，锁定部件不移动。Shift 限制为水平或垂直移动，空格和中键仍平移画布。拖动期间只更新预览，松手才保存一次，支持单步撤销/重做与 Escape 取消。右侧支持 X/Y 精确输入和恢复到原图位置。

位移记录在 Part2D.offset，源 PNG、遮罩、笔画和骨骼关节点保持原有坐标。渲染使用骨骼姿势变换乘图片位移，绘画和节点编辑将画布位置转换回图片源坐标，因此移动后仍能修补。位移参与骨骼回放及工程导出、重新导入；旧工程缺省 offset 为零。参考底图不作为可移动部件。

验证：tests/cutout-placement.test.ts 覆盖原位/动画坐标、负位移、重置、锁定和序列化；scripts/cutout-selection-smoke.cjs 使用真实指针检查直接拖动、透明区命中、锁定、撤销/重做、取消、缩放后坐标、移动后绘画、位置导出及重启恢复。

## 三视图裁切（0.10.15）

「拆分部件」工具栏增加「裁切参考图」（C）。导入合并三视图的 PNG 后，在原图上拖出矩形框；框内拖动移动，四角和四边拖动调整范围；右侧可输入整数 X、Y、宽度、高度或选择整张原图。框始终限制在原图范围内，支持反向框选、缩放、空格 / 中键平移、撤销重做。绘制或拖动时按 Esc 取消当前调整。

输入图片名后点击「保存裁切 PNG」，使用原生保存对话框选择文件夹和文件名，默认 Worktree。导出保持原始像素和透明度，不包含选区、裁切框、网格或骨骼。原始参考图、临时部件选区与已拆部件不受影响；可重复调整裁切框分别保存正 / 侧 / 背面。保存后重新「导入角色图」导入单个视图，即可开始后续部件拆分。裁切本身不将已有部件坐标转换到新画布。

裁切框保存在 `reference.cropRect`，随工程自动保存并恢复，旧工程无此字段仍兼容。主进程校验实际 PNG、尺寸和体积，原子写入并拒绝替换文件夹和符号链接；取消保存不写文件。保存到 Worktree 后刷新项目文件树。

实现：`src/shared/cutout-crop.ts`、`src/ui/CutoutCropOverlay.tsx`、`electron/cutout-crop.ts`。测试：`tests/cutout-crop.test.ts`；桌面专项：`scripts/cutout-crop-smoke.cjs`（`--packaged` 检查安装包），包含真实鼠标框选 / 移动 / 边角调整、数值输入、撤销重做、取消保存、自选文件夹、逐像素和透明度、工程恢复以及裁切 PNG 重新导入。输出位于 `output/cutout-crop-review`。

验收结果：228 项测试通过；macOS 0.10.15 安装包裁切专项通过，导出 256×256 中间视图并验证逐像素颜色及透明通道，切换工程恢复裁切框，重新导入导出 PNG 可继续拆分。现有 2048px 原图连续部件选择与动作检查回归通过，拖动笔画期间底图重画为 0，原图替换后分析缓存正确失效。

## AI 部件补画（0.10.16）

拆分后的下一步进入独立的「AI 部件补画」阶段。左侧逐个选择部件，中间对照透明底图与 AI 候选，右侧输入补画要求并生成。部件补齐隐藏轮廓、关节连接和缺口后，用户点击「采用此补画」；完整部件可以明确标记「无需补画」。参考原图工作流中，所有部件确认后才开放装配与动作检查；既有无参考图的分层样例仍可直接装配。

接入已有 OpenAI 图片编辑任务和设置，不新设密钥。当前部件栅格化为独立透明 PNG，按可见像素紧缩并预留 24px 起的边距；附角色原图作为第二张风格和结构参考。透明区域作为可补画区，可见像素通过遮罩及本地合成保留。结果要求透明背景；AI 输出的内容质量仍需用户检查，不能据此保证隐藏结构一定正确。

任务与结果保存在当前工作台，生成完成不修改部件。明确采用时才替换对应位图及其注册矩形，移除旧选区 / 遮罩以显示新增像素，并保留关节点、绑定、位移与层级、原图和其他部件。一次采用可以撤销重做。原始部件内容签名用于拦截已过期候选；改名、透明度和位置调整不会迫使用户重新生成。重新拆选部件会回到原图注册并清除补画确认。

每次点击只提交当前部件一次，不自动批量生成或重试。提交状态不确定时阻止新请求，用户检查供应商记录后可明确结束本地跟踪（不重发、不宣称撤销远程生成）；本地保存失败提供「重试保存结果」。接口未配置时显示设置入口。制作阶段与部件确认状态随工程保存，候选任务保存在当前工作台，重开装配阶段恢复移动工具和拼合视图。

实现：`src/shared/cutout-repair.ts`、`electron/cutout-repair.ts`、`src/ui/CutoutRepairStage.tsx`；测试：`tests/cutout-repair.test.ts`。`scripts/cutout-repair-smoke.cjs` 使用模拟图片接口检查完整桌面流程，`--packaged` 检查安装包。模拟响应验证流程和像素保护，不代表实际模型的补画质量；测试不调用付费接口。报告与对照截图位于 `output/cutout-repair-review`。

0.10.16 验收：232 项测试、类型检查与 macOS 打包通过；安装包 AI 补画专项使用模拟图片接口验证逐个生成 / 确认、像素保护、透明度、新增范围、撤销重做、注册保留、导出及重开后的工具 / 视图恢复，付费调用为 0。安装包原有连续拆分、部件移动、关节绑定、动作回放及三视图裁切回归通过。实际模型的补画质量尚未用真实 API 验收。


## AI 骨架生成与编辑（0.10.17）

在「装配与绑定」右侧点击「AI 自动生成骨骼」。使用配置中的 OpenAI 模型与 Key，发送当前装配后的透明 PNG（不发送原始三视图）和部件 ID、名称、注册矩形与位移；模型按角色结构生成骨架，不强制人形模板。坐标按整张画布归一化，主进程校验单根、无环、有效坐标和每个部件的唯一绑定。一次点击一次请求，生成中的重复提交被拒绝。

生成完成先在画布预览，模型说明展示不确定信息；点击「应用骨架」才修改工程。角色在生成期间或预览后发生变化时拦截过期结果。应用替换骨骼与绑定，旧动作重置为静止片段；界面明确提示，整个应用操作可以撤销。未应用的预览不持久化，离开阶段后清除；已应用的骨骼、名称和绑定随工程自动保存及 ZIP 导出。

点击「编辑骨骼关节」后可拖动画布关节点，或选择骨骼修改名称、世界坐标和父节点。父节点菜单排除自身与后代；根节点不允许删除或改父节点。支持添加子骨骼；删除时将直属子节点和关联部件转给父节点，并移除该骨骼的动作通道。设置姿势编辑保留其他关节的世界变换与部件的原始图像注册，不会因改肩关节而误移肘部或图片。部件属性中的「绑定骨骼」继续支持手动重绑，动作检查的转角滑块用于确认接缝。

## 先排布图层，再生成骨骼（0.10.18）

## Prompt 生成骨骼动作（0.10.20）

「动作检查」后新增第五步「AI 生成动作」，检查面板提供下一步按钮。已绑定可转动骨骼的部件可开始生成；未绑定时提供返回装配入口。右侧输入动作 Prompt（最多 2000 字符）、0.5–15 秒时长和是否循环。Prompt、时长、循环及当前选择的动作自动保存到工程的 `motion` 字段，制作阶段保存为 `workflowStage: motion`。

每次点击只调用一次配置的 OpenAI 视觉模型，发送静止装配图、编号部件图集、骨骼名称/父子关系/世界位置、部件绑定与用户动作描述。模型返回动作名称、说明和旋转关键帧。角度为相对于静止姿势的局部旋转增量，正值顺时针；沿用既有平滑插值与刚性切片渲染。当前引擎仅支持骨骼旋转，不包含平移、缩放、换图或网格变形；无法完整表达的动作由模型说明旋转近似的限制。

主进程校验关键帧严格递增、从 0 覆盖至完整时长、通道无重复且全部属于当前骨架、角度有限且不超过 ±180°。模型省略的通道补 0，循环动作首尾角度统一；没有能影响部件的动作变化则拒绝。生成期间互斥请求，工程修订不匹配时拒绝；不自动重试或修改工程。

## 完整切片轨道、模板与关键帧编辑（0.10.21）

保留已有角色、骨架与绑定，扩展既有 `Rig2D` / `Clip2D`，旧的纯旋转关键帧仍使用原有缓入缓出采样。新动作可选择连续曲线、线性、缓入缓出和保持；关键帧可覆盖整个动作的插值设置。连续曲线在中间关键帧保留速度连续性，减少每个姿势强制停顿。

### 第三步：骨骼用途与范围

关节编辑增加根、躯干、头、左右肩肘/髋膝/脚、配件等用途。未显式标记时根据骨骼名称推断，用户可覆盖。可开启相对静止姿势的角度范围（±180°内），AI 生成与模板会限制角度，播放也执行限制。编辑这些元数据保留原骨架的位置、层级和部件绑定。

### 第四步：检查完整变换

动作检查播放当前选中的完整轨道，不再只读取旋转。增加可选骨骼的 X/Y 位移、X/Y 缩放测试，与原有角度检查和恢复姿势并用；测试增量不会写入骨架或动作。

### 第五步：动作方式与 AI

- 自定义关键帧：AI 根据 Prompt、装配图、部件图集、用途/范围和替换图 ID 生成完整轨道。骨骼位移为父空间相对初始位置的像素增量，缩放为倍率；部件额外位移按静止画布坐标轴，附加旋转和缩放围绕绑定关节。
- 待机呼吸、原地行走、挥手模板：本地按骨骼用途重定向；可不调用接口先预览。AI 在模板模式只调整动作幅度、次数、身体起伏和躯干倾斜，再由本地模板产生受约束的轨道，避免任意编写整张角度表。缺少相关骨骼用途时提示补充标记。
- 模板的行走目前为原地周期动作，没有自动脚底锁定、碰撞检测或完整运动学求解。网格蒙皮不在本轮范围内。真实生成动作的自然度仍需实际角色人工验收。

### 轨道与换图

`keys[].rotations` 保留旧格式；新增 `bones` 的 x/y/scaleX/scaleY，及 `parts` 的额外位移/旋转/缩放、opacity、visible、z 和 variant。连续属性插值，显隐、层级和图片在关键帧时切换。稀疏轨道按上一个明确值保持或按相邻明确值插值，起始未设定时使用静止默认值。

在已保存动作的部件轨道中添加 PNG 替换图，再在相应关键帧选择图片。最多每部件 16 张，单张不超过 8 MB / 4096px，总工程仍受 24 MB 限制；换图保持该部件原有注册矩形，可用部件轨道微调。替换图独立于原有遮罩与修补笔画。它们记录为 artwork 的 variants 位图与 rig.parts 的 variants 资源路径；AI 只能引用已经存在的替换图，不能凭空生成新图片。

工程 ZIP 保留动画可能显示的静态隐藏部件及其可见性，运行时包含全部轨道、替换 PNG 和资源路径。替换图随 PNG 注册区域的扩展补透明边距，避免额外笔画扩大部件后导致换图错位。当前导出为 Laputa JSON/PNG 工程包，未实现 Spriter SCML 或饥荒 anim.bin 编译。

## 网格蒙皮与支撑脚锁定（0.10.22）

第三步选择部件，在「网格蒙皮」中选择影响骨骼及密度，生成规则三角网格与距离权重。支持拖动顶点、选择骨骼后涂抹/减去权重、按顶点精调和重新计算；每点最多四个骨骼且自动归一化。顶点移动保留 UV，蒙皮采用当前骨矩阵乘逆静止矩阵的线性混合，再用纹理三角形绘制。原有透明遮罩、补画、部件位移与换图沿用源画布注册坐标；无网格的部件保留整块绑定。可显示网格并在第五步切换蒙皮对照。这里没有独立形态键或逐帧 FFD 轨道。

同一步的「脚底骨链」可根据左右腿用途识别，或手动选择髋→膝→脚直接父子骨骼，设置膝盖方向、脚底局部坐标和地面 Y。识别时参考脚部图片透明边界；「在画布上设置脚底点」支持点击定位，随后保存骨链。骨链不能共享关节。删除相关关节会清理骨链及支撑区间；应用全新 AI 骨架会将网格权重重绑到新骨骼并清空旧脚底设置，界面提示且支持撤销。

第五步为每个动作配置支撑区间，可生成交替区间、添加/删除区间、使用自动落脚目标或指定 X/Y。行走模板在已有骨链时自动附带支撑区间；自定义 AI 会收到骨链和蒙皮信息，允许返回支撑区间，模型响应经过范围及重叠校验。已有动作可直接添加区间，无需再次调用 AI。

第四、五步共享动作求值器：在区间起点从原始动作确定落脚 X，以地面 Y 为目标，固定脚底朝向并调整髋、膝和脚的角度。求解遵守关节范围、不拉长骨段；目标不可达时显示误差。拖动时间轴独立求值，不依赖播放历史。关闭动作锁定可对照原动作。自动化指区间内 IK 锁定及模板支撑标注；没有地形碰撞、动力学或自动身体平衡，复杂动作需要编辑支撑时间和目标。

网格、UV、权重、脚底设置与支撑区间均保存在工程及运行时 JSON，PNG 保留注册坐标；外部播放器需实现同样的蒙皮和 IK 求值，尚未导出饥荒原生动画格式。

默认界面为「拆分部件 → 和 AI 制作动画」。用户手动拆分后描述效果，AI 可自动排布与绑骨、识别骨骼用途、生成网格和初始权重、识别脚底骨链并生成动作。高级编辑保留原五阶段、手绘修补、骨骼树、网格、权重和关键帧工具；编辑模式随工程保存。

导演通过严格 JSON Schema 返回有类型的操作计划，执行器仅允许已实现的工具，所有本地变换经过工程校验。工具包括自动准备角色、创建动作、调整指定骨骼的动作幅度/时长、生成部件网格、局部权重涂抹、移动关节、修改绑定与部件位置/层级、设置用途、配置脚底。已有可用骨架和手工网格在自动准备时保留。每轮最多12项操作，最多各一次自动准备和动作生成；初次全流程最多4次制作模型请求，加1次视觉检查。视觉检查可执行最多4项本地修正，无自动递归生成。

## 整体上下文补画（0.10.27）

AI 导演可通过 `repair_part` 发起一个部件的补画；例如“补齐右上臂被衣袖遮挡的根部，保持原有线条和配色”。高级编辑 → AI 部件补画使用同一套控制器。一次导演请求只执行一个部件补画，采用或放弃后继续动画对话。已有导演骨架候选也可作为补画基底，采用时一起写入共享工程。

输入顺序为独立透明部件、当前完整装配、带目标与关节点标记的完整装配、接缝局部、可用原始角色图。无原图也会渲染前三种上下文。视觉模型规划1–4个归一化矩形，总面积最多75%；本地遮罩保护原有不透明核心及区域外像素，允许1–3px窄接缝修整。输出维持输入尺寸和原图注册位置，其他部件不变。使用当前配置的 OpenAI 视觉模型分析/回看，图片模型执行补画。

生成后用实际蒙皮渲染器装回角色，提供静止、目标影响关节±20°（服从关节限制）及可用动作25%/75%时刻的前后对照。第一版回看发现明确问题时，在原始部件和相同局部遮罩上修正一次，然后再次回看；最多两次图片生成。不是连续视频验收，真实画质仍依赖模型和部件素材。第二次失败保留第一版候选，可采用、手绘或放弃；中断回看可以手动继续。停止仅阻止后续步骤，已提交请求可能继续。
