# 二维角色小闭环实验

本实验验证二维角色生成与骨骼动画之间的资产流程，不接入正式工作台。

## 实际执行范围

- 使用现有 `electron/providers.ts` 生图接口，真实提交一次带姿势参考的请求。
- 单张正面机器人：12 个源部件，3 个独立隐藏接点补片，13 个层级节点。
- 按查看后的实际图像人工登记遮罩和关节。并未实现自动语义拆件。
- 刚性切片绑定；一个 2 秒、30 fps 的手臂弯曲动作。
- 动作由确定性角度关键帧驱动。双骨 IK 另有单元验证；未调用动作 API。
- 自定义 ZIP 包保存 PNG、完整文档和逐文件 SHA-256；回读后检查渲染。

不覆盖三视图一致性、网格蒙皮、自由转身、复杂衣物、自动补画、动作 API、Spine/Unity 等运行时兼容性。

## 坐标与数据契约

`src/shared/skeletal2d.ts` 使用源图片像素坐标，Y 向下、正角顺时针。
骨骼原点位于父节点局部空间，关键帧角度叠加到参考姿势。
部件保留源画布裁切位置，绘制变换为 `worldPose × inverse(worldBind)`。
因此裁切优化不会重新定义轴心。此实验 left/right ID 指图像左右，
正式动作适配前还需要单独登记人物解剖左右，不能直接把实验 ID 当作 API 人体标签。

隐藏补片具有独立身份和开关，保留原像素。它们是人工构造的圆形关节余量，
只证明补全在流程中的作用，不代表服装或人体的最终美术方案。

## 实际发现的问题

1. 生图保持了 T 姿势，但改变了图像比例和部件位置。不能复用参考坐标直接绑定，
   需要生成后的注册步骤。
2. 初次按 X 区间拆上臂时，把躯干右缘的像素一起切走。弯臂后出现随手臂移动的细线。
   数学接点仍然正确。已通过限定手臂区域修正，并加入活动部件裁切范围检查。
3. 可见部分直接切开缺少隐藏接点，弯肘后存在透明缺口。人工补片降低了选定肘部
   探测区的透明像素数：152 → 0。该探测区不代表整个角色的美术验收。
4. 白底图的抗锯齿边含背景色，暗背景下仍可见浅边。当前白底移除只适用于本样例，
   正式流程需要透明边缘修色和用户可修正遮罩，不能直接推广到含白色材质的角色。

## 验证结果

- 5 个单元测试通过，包括独立目标 IK、不可达报告、轴心保持、循环与非法数据。
- TypeScript 类型检查通过。
- 不加补片、静止状态重组源部件，Canvas 像素通道差异为 0。
- ZIP 导出回读，13 个采样帧渲染结果一致。
- 层级连接误差最大约 `2.05e-13` 像素。
- 破坏 PNG 内容后，哈希检查拒绝导入且保留现有文档。
- 已查看最终预览和补片前后图，误归属的躯干细线已消除。
- 接缝轮廓与白色边缘仍需美术精修；数值结果不视为成品质量通过。

## 重现

输出位于忽略目录 `output/skeletal2d-review/`。`index.html` 内嵌素材，支持离线播放、
逐帧、接点显示、隐藏补全开关、ZIP 下载和回读；`arm-bend.gif` 为实际切片动画。

已有生成图时，不再发送请求：

```sh
node --import tsx scripts/skeletal2d-review.ts
node_modules/.bin/electron scripts/skeletal2d-smoke.cjs
node --import tsx --test tests/skeletal2d.test.ts
npm run typecheck
```

首次真实生图入口为 `scripts/skeletal2d-generate.ts`，需经 esbuild 打包到
`output/skeletal2d-tools/generate.cjs` 后运行 Electron。凭据只在进程内解密使用，
不写入输出。请求记录存在时脚本拒绝再次提交；状态不确定时应先核实结果。

下一轮应使用一个具有真实遮挡和服装的二维角色，先证明可修正的部件拆分与隐藏区域
补全，再接动作 API。动作 API 的输出须转换为明确的骨骼层级、参考姿势、坐标、
时序和约束；此轮没有证明任何具体动作服务支持二维骨骼。
