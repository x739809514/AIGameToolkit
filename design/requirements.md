# AI Assets Toolkit 需求与交互设计

用户在一个界面中完成图片和视频创作：先通过图片聊天窗口生成图片，在中间预览、选择，再把图片应用到视频聊天窗口，输入视频 prompt，由 MiniMax H3 生成视频并在右侧播放。

版本：MVP 初稿。日期：2026-10-11。

## 1 已明确的需求

| 编号 | 需求 | 完成表现 |
| --- | --- | --- |
| R01 | 设置中接入大模型 API，首先支持 ChatGPT 和 Claude | 可配置 OpenAI、Anthropic 凭据并选择聊天模型 |
| R02 | 设置中接入 MiniMax H3 API | 可配置 MiniMax 凭据和 H3 视频模型 |
| R03 | 左侧上下两个聊天窗口 | 上方生成图片，下方生成视频，历史和输入框独立 |
| R04 | 两个聊天窗口都可上传文件、图片、视频 | 可添加、查看、移除附件，并说明附件处理结果 |
| R05 | 中间为图片 preview | 发送图片 prompt 后显示生成图片 |
| R06 | 图片可应用到视频聊天窗口 | 所选图片成为明确可见的基础图片 |
| R07 | 右侧为视频 preview | 视频窗口发送 prompt 后调用 H3，完成后可播放 |

本项目中的“ChatGPT API”按 OpenAI API 接入实现。聊天模型、图片生成模型、视频生成模型分别配置；不能把三者当成同一种能力。

## 2 首版建议范围

产品定位已确定为桌面 App，以可安装的桌面应用交付，首版实现面向 macOS Apple Silicon。首版建议按单用户、本地保存数据、桌面宽屏使用设计，界面默认中文。图片与视频生成通过联网调用供应商 API 完成。

首版包含：API 设置、双聊天窗口、双预览窗口、素材上传、图片生成与继续修改、图片应用到视频、视频异步生成、下载、基本历史和重启恢复。

账号体系、多人协作、云同步、时间线剪辑、批量生成、复杂分镜、音频单独编辑和移动端适配放在后续版本。MVP 默认每次生成一张图片或一个视频，但保存每次结果，避免覆盖历史。

## 3 主界面

```text
┌─────────────────────────────────────────────────────────────────────┐
│ AI Assets Toolkit                 当前项目 / 保存状态       设置     │
├─────────────────────┬───────────────────────┬───────────────────────┤
│ 图片聊天            │ 图片 Preview          │ 视频 Preview          │
│ 聊天模型 / 生成模型 │                       │                       │
│ 消息与生成记录      │ 当前选中的图片        │ 当前选中的视频        │
│ 附件 / prompt       │                       │                       │
│ [上传] [发送生成]   │ [缩放] [下载]         │ [播放] [全屏] [下载]  │
├─────────────────────┤ [应用到视频]          │                       │
│ 视频聊天            │                       │                       │
│ 基础图片卡片        │ 图片历史缩略图        │ 视频历史缩略图        │
│ 消息与任务状态      │                       │                       │
│ 附件 / prompt       │                       │                       │
│ [上传] [发送生成]   │                       │                       │
└─────────────────────┴───────────────────────┴───────────────────────┘
```

建议三列初始比例为 34% / 33% / 33%，允许拖动分隔线；左侧上下初始各占一半。各自独立滚动，输入区固定在所属聊天窗口底部。窗口变小时允许收起预览，保持输入可用。

图片预览提供适应窗口、缩放、下载、历史选择和“应用到视频”；视频预览提供播放暂停、进度条、音量、全屏、下载和历史选择。空状态说明下一步操作；生成时保留已有结果，叠加新任务状态。

## 4 API 设置

| 设置区域 | 首版字段 | 用途 |
| --- | --- | --- |
| OpenAI | API Key、聊天模型、图片模型、连接测试 | 聊天理解、prompt 整理、图片生成 |
| Anthropic | API Key、Claude 模型、连接测试 | 聊天理解、素材分析、prompt 整理 |
| MiniMax | API Key、H3 模型、连接测试 | 视频生成 |
| 默认行为 | 默认聊天模型、图片参数、视频参数、保存位置 | 减少重复配置 |

API Key 支持录入、替换、删除和掩码显示。模型选择与可用能力关联，模型 ID 不散落硬编码在界面。服务地址使用供应商预设，地区及自定义地址作为高级配置按需开放。

“连接成功”与“可以生成”分开显示：凭据有效不保证账号有指定模型权限或足够余额。连接测试不默认创建收费视频任务。

Claude 在本方案中负责理解和整理需求，图片仍由独立图片服务生成。仅配置 Claude 时，图片窗口应提示补充图片服务配置；仅配置 OpenAI 图片服务和 MiniMax 时，允许直接使用原始 prompt 完成核心流程。

## 5 图片聊天与生成

1. 用户输入 prompt，可选添加图片、文档或视频素材。
2. 窗口显示实际使用的聊天模型与图片生成模型。
3. 默认“发送生成”会产出图片；可另外提供“讨论”模式，专门分析素材或调整构思。
4. 若启用 prompt 优化，先由所选聊天模型整理需求，保留原始 prompt 和实际发送的 prompt；优化失败应明确报错或提供按原文继续的操作。
5. 调用图片生成服务，消息区显示任务卡，中间显示生成状态。
6. 完成后保存图片并自动展示新结果。失败保留 prompt、附件和上一张图片。
7. 用户可以选择历史图片继续修改；任务明确记录作为参考的图片，避免“修改上一张”指向错误结果。

## 6 图片应用到视频

1. 在图片预览中选定一张图片，点击“应用到视频”。
2. 视频输入区出现基础图片卡片，包括缩略图、来源和移除按钮，并切换为首帧图生视频模式。
3. 保留视频窗口已经输入的文字，将焦点移动到视频输入框；此操作不自动开始生成。
4. 已有基础图片时替换为新选择，可撤销；正在执行的视频任务继续使用提交时的图片快照。
5. 视频任务记录图片资产 ID 和版本，不依赖“当前预览图片”这种会变化的状态。

建议将“基础图片”默认定义为视频首帧。如果用户需要只参考人物或画风，可显式切换到参考素材模式，不能静默改变图片用途。

## 7 视频聊天与生成

默认流程是“基础图片 + 视频 prompt → 视频”。用户可描述人物动作、镜头运动、节奏、环境变化等。

发送前校验凭据、prompt、基础图片、模式和参数。提交后立即显示任务卡和等待状态，后台持续查询，成功后在右侧显示视频。支持下载并查看生成参数；再次发送产生新的任务和结果。

首帧模式要求有基础图片。建议同时提供参考素材模式，让上传的视频可作为直接参考；无图片的纯文生视频可后续开放。

## 8 两个窗口的素材上传

两个窗口共用上传组件，但附件属于各自会话。支持选择文件、拖放和图片粘贴。文件先进入本地资产库，发送时按其用途交给对应服务。

以下格式为产品首版支持范围建议，实际供应商限制见技术方案。

| 类型 | 首版格式 | 图片聊天用途 | 视频聊天用途 |
| --- | --- | --- | --- |
| 图片 | PNG、JPEG、WebP | 视觉参考或修改输入 | 基础图片或参考图片 |
| 视频 | MP4、MOV | 抽取关键帧供视觉分析 | 参考模式直接输入，或抽帧辅助描述 |
| 文档 | TXT、Markdown、PDF | 提取文字形成创作要求 | 提取剧本、动作或镜头要求 |

视频抽帧不等于完整理解视频，首版不默认识别音轨。扫描 PDF 无可提取文字时提示原因，OCR 可后续添加。未知格式明确拒绝，不能显示已使用却实际忽略。

每个附件标明“基础图片”“生成参考”“仅用于分析”或“未使用”。预处理进度、大小、缩略图、失败原因和移除操作可见。超出模型数量、体积、分辨率或时长限制时，发送前提示。

H3 的首帧图生视频与参考素材模式不能混用。首帧模式上传视频时，用户需选择将视频仅用于分析，或切换到参考素材模式。切换前展示基础图片用途的变化。[MiniMax 创建任务文档](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)

## 9 状态与异常

- 两个聊天窗口可各自生成，任何任务不得冻结整个工作台；首版建议每个窗口同时执行一个生成任务。
- 明确区分素材处理中、提交中、排队中、生成中、保存中、完成、失败和连接中断。
- API 未给出进度时显示阶段与已等待时间，不展示虚假百分比。
- 处理无效密钥、余额不足、限流、网络断开、素材不支持及供应商拒绝，并提供对应操作。
- 网络超时不等于服务端失败；已取得任务 ID 时继续查询，避免自动重新创建收费任务。
- 文件下载失败时允许只重试保存结果，不重新生成。
- 不承诺关闭窗口或停止查询会取消远程生成，也不承诺退费。

## 10 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 首次配置 | 可分别保存并测试三个供应商，密钥不明文回显 |
| 文本出图 | 图片窗口发送 prompt，中间出现可下载的真实图片 |
| Claude 辅助出图 | Claude 整理需求后调用已配置的图片服务，最终有图片结果 |
| 素材上传 | 两个窗口均可接收支持的文件、图片、视频，并显示真实处理用途 |
| 图片交接 | 点击应用后，视频输入区准确显示所选图片，已有文字保留 |
| 图生视频 | 发送动作 prompt 后实际调用 H3，右侧可播放和下载结果 |
| 视频参考 | 参考模式的视频输入生效；首帧模式与视频参考冲突被明确处理 |
| 历史独立 | 图片与视频历史不串联污染，旧结果可查看 |
| 任务恢复 | 重启后保留素材、消息与任务 ID，可恢复查询未完成的视频任务 |
| 失败恢复 | 错误有原因，输入不丢失，不因网络超时自动重复付费生成 |

## 11 开发前需要确定的选择

这些选择不影响当前需求梳理，开发阶段再定稿。

| 选择 | 暂定建议 |
| --- | --- |
| 首发操作系统 | 首版 macOS Apple Silicon；其他操作系统后续扩展 |
| 图片供应商 | 首版 OpenAI 图片生成，预留其他供应商接口 |
| 基础图片的含义 | 默认视频首帧，参考模式显式切换 |
| prompt 优化 | 可开关，默认直接生成，避免隐藏改写 |
| 数据保存 | 本地项目与资产目录，首版无云端账号 |
| 生成默认参数 | 开发时按实际账号可用模型选择，允许用户修改 |
