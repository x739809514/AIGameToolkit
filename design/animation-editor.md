# 本地 3D 动作编辑器（0.6.0）

2026-10-12。按最新需求替换第二种工作台模板；图片与视频创作保持原有界面和功能。

## 当前范围

先完成已有模型与动作的导入、播放和观察。左侧不再显示聊天、Prompt、静态图 AI 解析、视频生成和二维拆帧流程。这个模板不调用 AI，不需要 API Key。后台拒绝此模板的新生成、解析及任务重试请求，不恢复其历史生成任务查询。

Gallery 中模板名为「动作编辑器」，内部类型为 motion-editor。旧 video-frames 实例原地转换，保留 ID、Worktree、目录、素材、历史任务和原 SQLite；自动生成的“视频与动画帧”名称更新，自定义名称保留。历史流程代码仅作为兼容数据和回归测试保留，不作为新编辑器入口。

## 实现

- 导入二进制或 ASCII FBX，检查扩展名、文件签名及 50 MB 上限，保存原始字节。模型读取、播放配置保存使用绑定工作台的 IPC。
- Three.js FBXLoader 在本机解析模型、骨骼和 AnimationClip。真正加载用户上传的网格与骨骼，不生成替代角色。
- 右侧 WebGL 透视相机、灯光、地面网格和 OrbitControls。根据实际模型边界自动取景；鼠标左键环绕、滚轮缩放、右键平移；支持正面／侧面／顶部／重置。
- 左侧模型文件列表、动画片段列表、模型与骨骼层级；网格节点选择显示边界框。
- 底部 AnimationMixer 播放／暂停、时间轴定位、首尾定位、0.25–2 倍速、循环。播放配置与当前文件随工作台保存；切换回来重新加载原文件。
- 无动画时查看静态模型；只有骨骼时显示骨架并提示；无可显示内容或解析失败时显示错误，可重试或替换文件。
- FBX 的外部贴图不向网络或原始任意磁盘路径请求，缺失贴图使用基础材质；嵌入贴图可显示。完整角色需要包含网格的 FBX。
- 切换工作台时停止 RAF、释放 Controls、Geometry、Material、Texture 和 WebGL 上下文，旧异步读取不会覆盖新工作台。
- 下载原始 FBX 使用系统保存对话框，保留原始二进制内容。

使用 Three.js 官方 [FBXLoader](https://threejs.org/docs/pages/FBXLoader.html) 和 [OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)。部分旧版 FBX 不受 Loader 支持，需要在 Blender／DCC 中重新导出。

## 0.6.2 当前相机视频导出

- UI：右侧“导出视频”，配置动画范围、720p／1080p、24／30／60 FPS；默认完整动作一次、1080p、30 FPS，显示预计尺寸与时长。
- 相机：开始时复制透视相机与投影矩阵，保持预览比例，按偶数像素确定输出宽度。按当前播放速度采样，继承忽略位移、网格与骨骼设置；关闭选中网格的边界框。
- 渲染：暂停 RAF 与相机控制，用离屏 WebGLRenderTarget 逐帧渲染并异步读取 RGBA；采样时间为 start + frameIndex × speed / fps，终点不重复。
- 编码：每次发送一帧，经工作台绑定 IPC 写入本地 FFmpeg 标准输入，使用背压限制内存。H.264、yuv420p、MP4、无音轨，vflip 校正 WebGL 像素方向。视频色彩按 sRGB 渲染。
- 完成：保存为当前工作台的真实视频 Asset，弹窗提供播放预览与系统保存对话框。
- 恢复：完成、失败、取消后恢复原时间、播放状态、辅助框与相机操作；原 FBX 不变。
- 生命周期：任务独立绑定工作台，阻止运行中删除；取消、离开工作台与退出时停止编码、清理临时文件。任务空闲超过两分钟自动清理。编码导入过程中取消不提交素材。
- 限制：导出最多 5 分钟、200 MB，视频尺寸为偶数像素且不超过 4096 像素单边及 4096 × 2160 总像素；不录制相机移动，无音轨。

验证覆盖范围／速度采样、非法参数、真实 H.264 编码的帧数与时长、方向校正、工作台隔离、临时文件清理，以及实际 FBX 相机视频导出、预览、保存、取消和播放状态恢复。

## 0.7.0 基础人形与 FBX 动作应用

按最新需求，右侧默认显示内置基础人形，上传 FBX 的网格不再作为预览角色。原文件仍保存，动画播放列表和原件下载保留。

基础模型仅使用用户指定的 Y Bot.fbx，保留文件的网格、材质、骨架和皮肤绑定，并映射 22 个主要控制关节。原件复制到 assets/models/y-bot.fbx，开发与打包时复制到 dist-electron/assets，由绑定 IPC 读取；不依赖用户 Downloads 路径或网络。原自建人形代码已删除，没有备用角色。没有上传动作时为静态 T 姿态，可使用相机、地面网格和骨骼显示。

动作流程：解析 FBX → 优先读取 SkinnedMesh 的实际骨骼（纯动画文件使用骨骼节点）→ 通过 Mixamo／常见人形名称别名匹配髋部、脊柱、头、双臂与双腿 → 捕获源／目标静止姿势 → 逐帧从源骨骼世界旋转相对静止姿势的变化计算目标局部旋转，按双方有效腿段长度比例传递髋部世界位移。基础模型骨段长度不被源动画覆盖。

预览层级显示基础模型的骨骼。状态栏显示匹配数及缺失骨骼；缺失关键髋部／双臂／双腿关节时拒绝映射，不能当作动作成功。可选脊柱分段、肩、头、手、脚、脚趾没有匹配时保留目标基础姿态并继承父关节。原始 FBX 不变，不再依赖原始网格或贴图。

现有原地播放、时间轴、调速、循环、相机与固定视角视频导出继续使用。视频渲染前先更新基础骨骼，完成后恢复源和目标姿态。卸载时同时释放原始 FBX 和基础模型的 Geometry、Material、Texture、Skeleton 和 WebGL 上下文。

当前自动映射适用于标准人形命名和静止姿势；非人形、特殊轴向与骨骼命名、额外骨骼层级可能需要后续手动映射和姿态校准。尚未实现脚底 IK／接触锁定、手指面部动画或重定向后的 FBX 导出。

验证覆盖基础骨骼绑定、固定身材、100 倍源比例、根位移和手臂姿态、缺失可选脚骨时比例正确、纯骨骼动作、原地播放，以及真实 FBX 对默认角色的播放、相机与 MP4 导出。基础角色截图：output/mvp-review/desktop-base-humanoid.png；输出动作第一帧：output/mvp-review/model-video-first-frame.png。

Y Bot 包含同名的控制骨骼和蒙皮叶节点。映射优先选择其实际 FK 控制父节点，让各网格的骨骼一起继承动作，避免只转动蒙皮叶节点而导致四肢脱离。原模型骨骼数量与主要映射关节数分别展示。

## 从项目文件树拖入 FBX 时间轴（2026-10-13）

右侧可读的普通文件支持拖动。时间轴读取文件的项目 ID 和相对路径，校验当前项目、文件类型与大小，从未登记的项目文件直接导入，加载实际动画并在落点插入片段；不用先经过素材卡片区。也支持 Finder 文件批量拖入，最多 12 个、每个 50 MB。重复拖入同一份未修改的项目文件会复用素材，新增独立片段；原文件保留。源文件变化后导入新的副本，既有时间轴片段继续使用原素材。

拖入图片／视频等非 FBX 文件时显示「文件类型不符合，动作时间轴只能拖入 FBX 文件」弹窗；混合文件批次在导入前整体拒绝。无可播放动画的 FBX 提示无法添加；文件签名不符、路径越界、其他项目或符号链接拒绝读取。弹窗可确认或按 Escape 关闭。导入期间显示加载状态，工作台切换后不再向已离开的预览写入片段。

本步骤只接入动作时间轴，聊天框和终端拖入继续按后续步骤实现。
