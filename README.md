# Laputa

桌面多工作台 App（0.8.12）。Dashboard 用 Gallery 显示「图片与视频创作」、「动作编辑器」和「终端」模板，以及已有 Worktree。多个工作台在同一主窗口中切换，各自保存素材和操作状态。

「图片与视频创作」保留图片／视频聊天、图片编辑和预览、MiniMax 视频生成。

「动作编辑器」取代原「视频与动画帧」模板，不接入 AI。打开工作台即可看到内置 Y Bot 基础模型。左侧显示角色真实骨骼的 Hierarchy，可展开、折叠和选择 117 个骨骼节点；右侧文件树选择已导入的 FBX 后，动作自动映射到基础模型，预览可环绕观察、缩放和平移。支持播放、暂停、时间轴定位、调速、循环、骨骼叠加和地面网格。旧模板实例自动转换，原文件与历史数据保留。

动作编辑器右侧下方新增单轨时间轴：从右侧文件树拖入 FBX 后，可重复添加、拖动排序，拖动卡片与前一片段重叠即可混合，拖开则吸附到末尾直接衔接；选中后仍可设置起点、终点、片段速度及精确混合时长。混合区域显示斜纹，最长为两个片段各自时长的一半。点击右侧文件树中的 FBX 预览单独动作；点击“动作时间轴”恢复组合播放。播放按钮、全局速度、循环和忽略位移统一位于新时间轴上方；点击或拖动标尺定位，旧播放滑条已删除。时间轴、裁剪与混合参数自动保存在当前工作台，导出视频包含组合和过渡效果。

「终端」使用真实的 macOS zsh 伪终端，默认目录为所属 Worktree。每个面板右上角提供 Show Chat View／Show Terminal View、Split Terminal Right 与 Close Terminal；最多同时打开 8 个独立终端，可水平滚动。切换工作台或显示方式不会重启 Shell。Chat View 使用自然语言与本机 Codex CLI 聊天，保留各面板独立的会话和上下文，支持继续追问、停止回复和复制消息；直接输入 Shell 命令及交互式程序通过 Terminal View 操作。需先安装 Codex CLI 并执行 codex login 登录。截图中的工作台标题与副标题已移除。聊天记录、分屏布局和视图偏好随工作台保存。重启 App 会开启新 Shell，不重新执行历史命令；关闭终端会结束对应进程，最后一个关闭后可重新新建。

当前版本为 macOS Apple Silicon MVP，使用 Electron、React、TypeScript 和 SQLite。真实 API 调用由桌面主进程完成。

动作编辑器工具栏的「2D 混合树」打开独立设置弹窗，可添加最多 16 个已导入动作，并为每个动作设置影响的骨骼。骨骼分层模式按列表顺序叠加，后面的动作按权重覆盖指定部位；支持上半身、下半身、左右肢体、头颈、躯干和逐关节选择。两个动作可使用「前两个动作：上身／下身」快速配置。2D XY 模式通过距离权重在动作节点间平滑混合，可拖动参数点或节点，包含相同位置的节点时按权重合并。它不等同于 Unity 的方向／Cartesian 插值算法。

混合弹窗包含独立的 Y Bot 实时预览、播放与定位，各动作按归一化进度同步到指定循环时长。填写新动作名称并点击「应用并保存新动作」，将当前混合结果烘焙为独立 FBX 并选中预览；取消不会新增动作。单动作、时间轴与混合树是可切换的预览模式，视频导出使用当前混合结果并记录参数。原始 FBX 保留。

## 打开应用

打包后的应用位于：`release/mac-arm64/Laputa.app`。可直接打开，或将其拖入「应用程序」。此构建供本地测试，尚未进行 Developer ID 签名和 Apple 公证。

## 选择与切换工作台

App 启动时在用户目录下创建 `~/Laputa`。新建 Worktree（项目）时，默认创建 `~/Laputa/<项目名称>`，例如 `~/Laputa/My Game`；重名目录自动加 `-2`、`-3` 后缀，避免覆盖已有文件。首次创建工作台时会建立 `~/Laputa/默认项目`。项目文件由用户管理，工作台数据库与素材缓存保存在 App 配置目录；终端默认进入项目目录，右侧文件树也显示同一目录。项目目录位置显示在 Dashboard 和新建对话框中。

已有项目继续使用原路径；旧版工作台数据库和已登记的素材缓存迁移到 App 配置目录，用户创建的文件保留在原位置。App 的 API 凭据、项目索引、工作台数据库和素材缓存保存在应用配置目录；终端内部 Shell 配置也放在配置目录，以支持中文项目名称。

启动 Dashboard 用 Gallery 卡片展示可用工作台模板和已有 Worktree。点击已有 Worktree 继续最近使用的工作台；空 Worktree 会打开创建工作台弹窗。点击「图片与视频创作」模板后，在弹窗中选择所属 Worktree、填写可选名称，再创建工作台。已有工作台在创作界面的左侧 Worktree 树中切换。

创作界面左侧是可展开和滚动的 Worktree 树。顶部加号只新建空 Worktree 文件夹；每个 Worktree 旁的加号在其中新建工作台。点击子工作台在同一主窗口切换。

一个 Worktree 对应 `~/Laputa/<项目名称>` 下的一个用户文件夹，新建时为空，不自动创建工作台、素材目录或数据库。工作台数据和生成结果保存在 App 内部，只有手动下载／保存才写入用户选择的位置。右侧文件树只展示用户项目文件，支持新建文件、新建文件夹、重命名、移动到目标文件夹、拖动移动，以及确认后移到系统废纸篓。切换同一 Worktree 中的工作台，目录保持一致；切换到其他 Worktree，右侧目录随之切换。在 Finder 或终端中修改项目文件后，文件树自动刷新。已下载的素材可继续预览或用于创作。

各工作台独立保存素材、任务、聊天、草稿和模型偏好，API Key 在整个 App 中共用。切换后原工作台任务继续处理，返回时恢复草稿与预览；新实例沿用同一 Worktree 中最近打开实例的模型偏好，后续修改仅影响本实例。

旧版本的创作数据归入“默认 Worktree”，保留原路径，无需手动导入。图片编辑器仍使用独立编辑窗口，并绑定到原工作台；切换主界面的工作台后，编辑结果仍保存到原工作台。

## 配置和创作

1. 创建或打开一个工作台，打开右上角「设置」或左侧「模型与设置」，填写 OpenAI、Claude 和 MiniMax API Key，点击保存。
2. 再次打开设置，可对已保存的凭据执行「测试连接」。此操作不会生成图片或视频，也不能替代模型权限和余额验证。
3. 在图片创作窗口输入 prompt，点击「生成图片」。可上传 PNG、JPEG、WebP、MP4、MOV、TXT、Markdown 或 PDF。
4. 在中间选中生成图片，点击「应用到视频」。已有的视频 prompt 会保留。
5. 在视频窗口描述动作和镜头，点击「生成视频」，等待右侧出现可播放的结果。
6. 图片和视频都可查看历史、下载到自选位置。关闭应用会保存草稿和记录；已提交的视频任务将在再次启动时继续查询。

默认不优化 prompt。开启「生成前使用聊天模型优化 Prompt」后，可选择 OpenAI 或 Claude；Claude 用于聊天和素材分析，图片仍由 OpenAI 图片服务生成。「仅讨论」会返回文本建议。

首帧模式仅使用一张基础图片。上传图片后可点击附件上的「设为首帧」。需要直接参考视频或多张图片时，切换到「参考素材模式」，避免混合首帧与参考素材角色。

图片创作窗口中的视频会抽取三张关键帧供聊天模型分析；这条路径需要聊天模型凭据。PDF 支持文字提取，扫描件无文字时会提示，首版不含 OCR 或音轨转写。文件最多 50 MB，实际发送时还会按目标模型校验数量、尺寸、时长、编码和请求大小。MOV 参考视频会转换为 MP4 容器用于传输，保留原件。

## 修改图片

中间图片预览区新增「画笔修改」「裁切」「去除背景」工具，点击后打开独立编辑窗口。上传的图片与生成图片都可编辑。

- 局部修改：画笔涂满目标区域，或用自由圈选围住目标，输入修改 Prompt 后提交。支持调整画笔大小、擦除选区、撤销、重做、全选。应用将遮罩发送给 OpenAI 图片编辑 API，并保留选区外的原始像素。
- 裁切：拖动选择区域，或输入 X、Y、宽度和高度，保存为新的 PNG。在本机完成，不需要 API Key。
- 去除背景：调用已配置的 OpenAI 图片 API，保存透明 PNG；可以补充需要保留的主体细节。此操作处理整张图，不使用画笔遮罩。

编辑结果保留原图，添加到历史并同步回工作台；随后可以应用到视频作为基础图片。透明区域显示棋盘格。支持恢复原图、缩放与下载；有未提交的圈选或文字时，关闭窗口会询问是否丢弃。

局部修改和去背景需要 OpenAI Key 与支持相应能力的图片模型，属于收费 API 操作。编辑器支持最多 1600 万像素的图片。

## API 调用

右上角「API 余额」显示已接入账户的余额状态，可展开查看明细、手动刷新或打开服务商账单。MiniMax 中国区尝试使用平台余额接口读取可用额度，每 5 分钟刷新；该接口未列入公开 API 文档，失效或权限不足时会提示查询失败并保留控制台入口。OpenAI、Claude 的普通 Key 当前未接入余额查询，显示「控制台查看」，不将消费金额或未知余额当作剩余额度。凭据只在桌面主进程使用，余额缓存不会写入项目。

当前 MiniMax H3 使用**中国区 API**：`https://api.minimax.cn`。视频创作栏显示「API · 中国区」，设置页同时显示地区与地址。请使用 [中国区控制台](https://platform.minimax.cn/console/personal-info) 创建的 API Key；旧版本保存过海外区 Key 的用户需要替换为中国区 Key。

视频生成、任务查询和连接测试统一使用中国区地址。旧版已提交的任务保留海外区快照，查询仍使用提交时的地区；查询旧任务仍需要其对应地区的有效凭据。当前界面不提供地区切换。

所有生成和聊天都调用已配置的供应商 API。缺少对应凭据时会提示先配置，调用失败会显示真实错误。应用没有离线模拟生成入口。

## 网络错误排查

桌面 API 请求与视频下载使用 Electron 的网络栈，支持系统代理配置。MiniMax 创建视频任务等待响应最多 5 分钟；不会因超时自动再次提交。

失败提示显示具体服务、阶段和 API 主机。开启 Prompt 优化时，视频首先调用 OpenAI 或 Claude；若该步骤失败，会明确提示「视频尚未提交到 MiniMax」。可以在设置中测试对应服务连接，或关闭优化后使用原始 Prompt。

「提交结果待核实」表示创建任务的响应未收到，不能由本地错误判断远程是否已经创建。请先在对应地区的供应商控制台核对任务，确认后再决定是否生成。DNS、TLS、连接中断与请求超时会分别显示；网络传输失败时不会泄露密钥。

## 本地数据

SQLite 保存设置、消息、草稿、任务和素材记录；每个工作台都有独立 SQLite 和 `assets` 目录。可以在设置中打开当前工作台的数据文件夹。App 根目录的 `workbenches.json` 保存工作台列表，凭据仍保存在 App 根目录；新实例数据放在 `workbenches/<id>` 中。旧实例保留原来的数据路径。

凭据使用 Electron `safeStorage` 的系统加密后保存，界面只接收是否已配置的状态。系统安全存储不可用时，密钥仅在当前会话使用，不回退为明文保存。

网络超时且未收到任务 ID 时，任务会显示「提交状态待核实」，不会自动重新提交。已取得 ID 的视频任务可以恢复查询；视频下载失败时可以只重试保存。MiniMax 的任务查询范围为最近 7 天。

## 开发和验证

```bash
npm install
npm run dev
npm run build
npm test
npm run test:desktop
npm run package
npm run test:package
```

- `dev`：启动 Vite 和 Electron 桌面窗口。
- `build`：类型检查、前端构建和主进程构建。
- `test`：供应商请求契约、素材校验、快照、持久化、网络中断及下载重试测试。
- `test:desktop`：真实桌面交互检查；隔离测试数据保存在 `.local-data`，截图和报告保存在 `output/mvp-review`。
- `package`：生成当前 macOS arm64 桌面应用。
- `test:package`：直接运行打包后的 App，验证 SQLite、内置媒体工具和实际视频播放。

`npm run dev:ui` 仅用于浏览器界面预览，真实 API 和本地文件处理需通过桌面 App 使用。

## 使用动作编辑器

1. 在 Dashboard 选择「动作编辑器」，创建工作台；旧「视频与动画帧」实例也会进入新版界面。
2. 从右侧文件树选择已导入的 FBX 动作。左侧导入与卡片区已移除；将项目资源文件夹里的 FBX 从右侧文件树直接拖到时间轴，会自动加载并添加片段；也支持从 Finder 拖入 FBX。非 FBX 文件会弹窗提示类型不符合。
3. 选择动作后点击播放；拖动时间轴查看指定时刻。可以选择 0.25–2 倍速度及循环播放。勾选「忽略动画位移」后，根节点和髋部的 XYZ 位移固定在动作起始位置，角色原地播放；保留肢体动作与旋转，取消后恢复原始位移。开关状态随工作台保存，原始 FBX 不变。
4. 右侧左键拖动环绕模型，滚轮缩放，右键拖动平移；顶部提供正面、侧面、顶部和重置相机。
5. 在左侧 Hierarchy 展开角色骨骼，可查看手部、手指与变形节点；用预览中的「骨骼」开关叠加显示骨架。本轮不提供武器绑定。

基础模型仅使用用户提供的 Y Bot.fbx，随 App 打包，不依赖 Downloads 路径或网络下载。保留原文件的网格与骨骼，自动映射 22 个主要人形控制关节。FBX 可包含角色网格，也可只有骨骼动画；预览统一使用基础模型。自动匹配 Mixamo 和常见人形骨骼名称，以静止姿势为参考传递关节旋转，按腿长比例缩放根位移，保持基础模型的骨段长度。匹配结果显示在预览下方；缺失可选骨骼保留基础姿态，缺失关键骨骼会提示无法映射。若 FBX 没有动画，可查看静态基础模型。当前不提供手动骨骼映射、脚底锁定／IK、非人形重定向和关节关键帧修改。时间轴支持动作组合，混合树可保存为新的 FBX。方案见 [动作编辑器](design/animation-editor.md)。

## 按当前相机导出动画视频

在动作编辑器中调整好相机和场景显示，点击右侧「导出视频」。选择动画起点、终点、720p／1080p 和 24／30／60 FPS，默认完整动作一次、1080p、30 FPS。宽度按当前预览比例计算，不强制切换到 16:9；视频时长跟随当前播放速度。勾选“忽略动画位移”时，导出同样使用原地动作。

点击「开始导出」后，本地逐帧渲染三维场景并编码为无音轨 H.264 MP4。进度显示渲染和编码阶段，可以取消。视频不包含按钮、鼠标、层级树或选中节点的边界框；地面网格与骨骼沿用当前显示设置。导出不会改变原始 FBX，完成或取消后恢复之前的播放进度及播放状态。

完成后在弹窗中预览，点击「保存 MP4」选择保存位置。生成视频保存在工作台内部缓存；只有手动保存到项目目录后才出现在右侧文件树。单次导出最多 5 分钟，结果最多 200 MB。输出时长按帧率取整，误差少于一帧。

本地测试生成的截图、视频和验证报告位于 `output/mvp-review`，不提交到 Git；运行相应验证命令后可查看设计文档中引用的本地报告。打包产物、用户数据、凭据和依赖也不入库。


动作卡片两端提供裁剪手柄：拖动左端调整源动作起点，拖动右端调整终点，时间轴实时显示片段长度。可以拖回恢复原范围，裁剪不修改原始 FBX。

右键时间轴卡片可改名或“另存为新的 FBX”。另存会把当前单个片段的裁剪范围和片段速度烘焙成独立 FBX，保存到当前工作台内部并选中预览；点击「下载当前 FBX」后选择保存位置，保存到项目目录后会出现在右侧文件树，原文件保留。FBX 另存使用本机安装的 Blender（macOS 路径 /Applications/Blender.app；Linux 路径 /usr/bin/blender 或 /usr/local/bin/blender），无需 AI API。


右键时间轴动作卡片可删除单个片段，源 FBX 保留；也可使用选中片段下方的删除按钮。左侧源卡片已移除，源文件管理操作后续改为文件树入口。其他动作及已导出视频保留，全部删除后恢复静态 Y Bot。原导入目录里的文件不动。处理素材或导出期间请等待完成后再删除。


骨骼混合默认保持每个动作的原始速度，按各自动作长度循环，避免短射击动作被长行走周期放慢。需要让走／跑动作按同一相位播放时，可开启“同步动作周期”；面板会显示实际调整速度。分层遮罩重叠时会显示被后层覆盖的骨骼，便于保留所需的上身动作。
